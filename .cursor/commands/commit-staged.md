# 스테이징 커밋: 메시지 작성 후 커밋

**목표**: 현재 스테이징된 변경만 읽어서, 그에 맞는 커밋 메시지를 작성하고 바로 커밋까지 수행한다.

## 절차

1. **스테이징 내용 확인**
   - `git diff --cached --stat` 로 변경 파일·통계 확인
   - `git diff --cached` 로 전체 diff 확인 (필요 시)
   - 스테이징이 비어 있으면 "스테이징된 변경이 없습니다"라고만 알리고 커밋은 하지 않는다.

2. **커밋 메시지 작성**
   - 변경 내용을 요약해 한글로 작성한다.
   - 형식: 첫 줄에 요약 (50자 내외), 필요하면 빈 줄 뒤 본문에 상세 항목 나열.
   - 예: `feat(mock): OOO 추가`, `fix(api): OOO 시 null 처리` 등 타입(scope): 설명 형태를 선호한다.

3. **커밋 실행**
   - 작성한 메시지로 `git commit -m "첫줄" -m "본문"` 형태로 실행한다 (본문이 있을 때만 두 번째 `-m` 사용).

## 주의
- 스테이징된 파일만 기준으로 메시지를 작성하고, unstaged/untracked는 반영하지 않는다.
- 사용자가 수정을 요청하지 않는 한, 커밋 메시지 초안을 길게 설명하지 말고 바로 커밋까지 진행한다.
